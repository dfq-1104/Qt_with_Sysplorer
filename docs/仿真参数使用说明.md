# 电池仿真界面参数使用说明

日期：2026 年 11 月 5 日。

以下说明对应当前工作树的实际模型和宿主插件。电池页设置新任务的初始条件；运行中调参页修改同一任务的后续控制输入，不重置当前 SOC 或仿真时间。

## 1 运行中调参的六个字段

| 字段 | 有效范围 | 作用及修改后的影响 |
|---|---|---|
| 工作模式 | 静置、恒流充电、恒流放电、恒压或限流充电 | 决定如何产生电流指令，是其他设定是否参与计算的前提。切换模式后其余输入值继续保留，不会自动全部改成适合新模式的值 |
| 恒流电流指令 | 0–5 A，输入正数幅值 | 恒流充电时请求正电流，恒流放电时请求负电流。增大后 SOC 变化通常更快，但仍受电流上限和截止保护约束。静置及恒压模式不使用这一字段产生电流 |
| 恒压目标 | 2.50–3.45 V，且不高于充电截止上限 | 仅恒压模式使用。模型根据目标电压与当前开路电压之差计算所需电流，再受电流上限约束。恒流模式下修改它不会改变当前电流指令 |
| 放电截止下限 | 2.50–3.45 V，且小于充电截止上限 | 当预计带载端电压达到或低于下限时封锁放电电流。调高一般会更早截止，调低允许更深放电；SOC 为 0 时仍封锁放电 |
| 充电截止上限 | 2.50–3.45 V，且大于放电截止下限 | 当预计带载端电压达到或超过上限时封锁充电电流。调低一般会更早截止；SOC 为 100% 时仍封锁充电。它是保护阈值，不是给电池强行施加的端电压 |
| 电流上限 | 0–5 A | 限制实际电流的绝对值，同时约束充电与放电。恒流指令 2.5 A、上限 1 A 时，未触发保护的实际电流为约 ±1 A；上限 5 A 不代表一定输出 5 A。设为 0 时实际电流为 0 |

当前界面在所有模式下都校验整组输入：`2.50 ≤ 放电下限 < 充电上限 ≤ 3.45 V`，`2.50 ≤ 恒压目标 ≤ 充电上限`。即使恒压目标在恒流模式中暂不参与电流计算，也必须满足提交约束。

### 四种模式如何计算

| 模式 | 电流指令 | 恒流电流指令是否生效 | 恒压目标是否生效 |
|---|---|---|---|
| 静置，模式 0 | 0 | 否 | 否 |
| 恒流充电，模式 1 | `+设定电流` | 是 | 否 |
| 恒流放电，模式 2 | `−设定电流` | 是 | 否 |
| 恒压或限流充电，模式 3 | `(恒压目标 − 当前开路电压) / 内阻` | 否 | 是 |

四种模式产生指令后，模型再做电流限幅和截止保护；结果曲线及电池读数显示的是实际电流，不是输入框里的设定值。

截图选择的是“静置”。因此，尽管电流指令为 2.500 A、上限为 5.000 A，实际电流仍应为 0，SOC 保持不变。当前模型没有自放电项；静置不是暂停求解，仿真时间仍会前进。

## 2 恒压模式需要特别区分的行为

当前模型使用内阻 `R0=0.01 Ω`：

```text
电流指令 = (恒压目标 − 开路电压) / 0.01
实际电流 = 电流指令限幅到 [−电流上限, +电流上限] 后，再检查截止保护
端电压 = 开路电压 + 实际电流 × 0.01
```

例如，假设当前开路电压为 3.26 V，恒压目标设为 3.30 V，所需电流为 4 A。电流上限为 2 A 时，实际电流被限制在 2 A，端电压约为 3.28 V，尚不能达到 3.30 V。随着 SOC 上升、开路电压增大，维持目标所需的电流会减小。

虽然界面模式名称含“充电”，当前方程没有把恒压电流的下限固定为 0。如果目标低于当前开路电压，指令会变为负数，并可能实际放电。例如，开路电压 3.26 V、目标 2.60 V 会算出 −66 A；电流上限为 5 A 时先限为 −5 A，再由放电下限判断是否放行。截图中的 2.60 V 在静置模式下不参与计算，切到恒压模式后就需要重新判断这一关系。本次标题调整没有修改这条模型方程。

此外，充电保护使用“达到或超过上限即封锁”的判据。当恒压目标等于充电截止上限，且限流不再使预计端电压低于上限时，可能直接封锁充电。因此，当前实现不能直接等同于完整充电器的标准恒流转恒压控制策略。

## 3 电池页的初始参数

| 参数 | 对新任务的影响 | 与运行中调参的关系 |
|---|---|---|
| 方向 | 选择起始的恒流充电或恒流放电，决定电流正负 | 运行中可通过工作模式切换，不会因切换重新设置 SOC |
| 截止电压 | 起始充电时作为充电上限；起始放电时作为放电下限。有效范围为 2.50–3.45 V | 起始充电的另一侧下限为 2.50 V；起始放电的另一侧上限为 3.45 V。运行中可以分别修改上下限 |
| 电流 | 新任务的恒流幅值，0–5 A；正负由方向决定 | 决定初始恒流电流指令；运行中的修改只改变之后的轨迹 |
| 起始电量 | 新任务从多少 SOC 开始，0–100% | 只在新任务初始化时设置；运行中调参不重置当前 SOC |
| 保存参数 | 保存客户端设置并更新预览，不向宿主写参、不触发求解 | 翻译或开始会重新读取当前输入，不要求先点击保存 |

“当前电量”“剩余 Ah”“实际电流”以及曲线中的端电压是状态或输出，不是额外可自由指定的输入。当前模型额定容量固定为 2.5 Ah，因此 SOC 为 50% 时剩余约 1.25 Ah。

## 4 哪些量会改变快慢

SOC 按实际电流积分。当前模型充电库仑效率为 0.995、放电为 1.0：

```text
dSOC/dt = 库仑效率 × 实际电流 / (2.5 × 3600)
```

忽略提前截止，2.5 A 放电对应约 1C，从 50% 到 0% 约需 1800 仿真秒；用 1.25 A 约需 3600 秒。2.5 A 从 50% 充至 100% 约需 1809 秒，差别来自充电库仑效率。保护封锁后实际电流为 0，SOC 就不再变化，求解仍可能继续到计划终点。

仿真倍速调整仿真时间相对墙钟时间的推进速度，不改变同一仿真时刻的物理参数或目标 SOC。20x 理想情况下表示每 1 秒墙钟推进约 20 仿真秒，实际速度还受计算性能限制。回放倍速只改变历史结果的播放速度，不影响求解。

计划终点在准备时按初始方向、电流和 SOC 估算，并限制在 120–20000 秒；零电流任务为 120 秒。运行中改电流或方向不会自动重新估算计划终点，所以修改后的充放电过程不保证恰好在当前终点前完成。

## 5 运行中修改何时生效

1. 输入框修改后还未向宿主提交，点击“提交运行中修改”才提交整组六个输入。
2. 正在运行时，宿主短暂停算、写入输入并继续；仿真时间和 SOC 不归零。
3. 原本已暂停时，修改暂存并保持暂停；继续后在后续模型采样处确认生效。
4. “已在仿真某秒由模型采样回读确认”表示该组输入已被实际模型采样确认，不表示实际电流必定等于电流指令，也不表示该时刻之后连接一直正常。

截图上方的 `UDP 通信超时，未收到 poll 的确认` 表示状态查询失联，运行参数控件因此禁用。下方 1481 秒的确认文字是之前已确认的记录，不能据此推断失联后的宿主当前状态。这个通信问题与删除重复标题是两件独立的事，本次没有扩大修改求解或通信逻辑。
