# 模型上传协议版本 1

沿用 schema=1 的请求封装、回环 UDP 发现令牌、TCP 身份认证与任务归属检查，不修改 TCP 帧认证算法。`hello` 除生命周期与宿主就绪状态外，必须返回 `modelTransferVersion:1`、`modelInterface:"battery-console/1"`。`modelHash` 仅表示宿主当前任务/模型，不是客户端连接许可条件。旧插件缺少能力时禁止开始任务。

请求中的 `client` 为上传归属；本次准备的 `taskId` 保持不变。插件会话重启后上传失效，客户端必须重新准备。每个客户端最多保留一份上传，宿主最多同时保留八个客户端的上传；空闲 60 秒清理。

| 命令 | args | 成功响应 |
| --- | --- | --- |
| `model.begin` | UUID `uploadId`、`modelTransferVersion=1`、`modelInterface=battery-console/1`、整数 `bytes`、小写十六进制 `sha256`、整数 `chunkSize` | `ok`、`uploadId`、`modelHash`、`committed` |
| `model.chunk` | `uploadId`、从零开始的整数 `offset`、严格 Base64 `data`、块 `sha256` | 同上并回显 `offset` |
| `model.commit` | `uploadId` | `committed=true`，且整体哈希已验证 |
| `model.abort` | `uploadId` | `ok=true` |

文本限 1…1048576 字节。UDP chunkSize ≤768，TCP ≤49152；除最后一块，长度固定等于声明值；offset 必须对齐块大小且不越界。重复块只接受相同数据，允许任意块顺序；commit 缺块报错，不加载部分文本。同一上传编号的 begin 必须有相同元数据。请求 ID 重传沿用原字节；与旧请求内容不同的同 ID 请求被拒绝。客户端逐块等待确认，沿用各传输既有超时与重试上限。

提交时验证长度、整体 SHA-256、UTF-8（禁止 NUL）以及固定模型命名接口。SDK 加载时再解析 Modelica，并检查固定参数与实时输入组件；解析、命名冲突和接口错误分别阻止后续翻译/启动。文本中额外依赖的 Modelica 库仍需宿主提供，不能凭传输文本自动安装第三方库。

`load/translate` 的 `args.modelHash` 必须指向该客户端已提交的文本。任务快照、实时状态、结果清单均记录此哈希。只有插件自己加载且未被用户修改的 `BatterySim` 可重用或替换；已有用户同名模型报 `MODEL_NAME_CONFLICT`，用户修改报 `MODEL_EDIT_CONFLICT`。不同文本不会复用旧求解器：每次任务使用独立目录重新翻译。相同文本可复用宿主模型类。

客户端准备时固定文本快照，Prepared 后再次读取文件哈希，变化则先 discard 并重新准备，运行中不热替换。上传失败不会清理历史任务结果。未完成上传不能触发任何 SDK 模型加载。

主要错误包括 `MODEL_SIZE_INVALID`、`MODEL_UTF8_INVALID`、`MODEL_INTERFACE_INVALID`、`MODEL_CHUNKS_MISSING`、`MODEL_HASH_MISMATCH`、`MODEL_CHUNK_*`、`MODEL_UPLOAD_NOT_FOUND`、`MODEL_NOT_UPLOADED`。它们与宿主忙、初始化、认证及连接失败保持分别报告。
