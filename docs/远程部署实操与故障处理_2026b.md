## 4. B 端首次部署流程

### 4.1 确认实际程序路径、账号和 IP

先正常打开准备使用的 Sysplorer 实例，然后在 B 执行：

```powershell
whoami
Get-Process mworks -ErrorAction SilentlyContinue | Select-Object Id, Path | Format-List
ipconfig
```

安装目录是 `Bin64\mworks.exe` 的上两级目录。本次实际是 2026b，不能继续照抄最初示例中的 2026a 路径。存在多个实例时，先确定需要更新的那个安装目录。

记录 B 正在使用网卡的 IPv4、掩码和网关。本次“以太网 2”的 `169.254.36.134` 为自动配置地址，没有网关，不作为本次 A 的连接目标。

### 4.2 解压并确认脚本存在

将服务器包完整解压。本次原包位置为桌面目录。确认：

```powershell
Test-Path -LiteralPath 'C:\Users\dfq\Desktop\BatteryConsole-Server-win64\Install-Server.ps1'
```

应返回 `True`。如果为 `False`，先找正确的解压目录，不要继续运行安装命令。

### 4.3 安装插件、端口和凭据

保存工作并关闭目标 Sysplorer，再使用管理员 PowerShell 执行完整的一行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\Users\dfq\Desktop\BatteryConsole-Server-win64\Install-Server.ps1' -SysplorerHome 'C:\Program Files\MWORKS\Sysplorer 2026b' -ListenAddress '0.0.0.0' -Port 39001 -Workspace 'C:\BatteryJobs' -ServerUser 'desktop-1pjilv4\dfq' -OpenFirewall
```

其他电脑请替换安装目录、运行账号和解压路径；任务目录使用可写的英文路径。`-ServerUser` 应是日常运行 Sysplorer 的账号，特别是提权终端与日常账号不同时。

安装后的实际文件：

```text
C:\Program Files\MWORKS\Sysplorer 2026b\Bin64\addins\BatteryUdpControl\
  battery_udp_control.dll
  remote.ini
```

脚本自动创建 `remote.ini`，启用指定端口，生成随机的 64 字符十六进制访问凭据，并把凭据另存到原服务器包的 `access-key.txt`。文件权限限制为指定运行账号、Administrators 和 SYSTEM。

`-OpenFirewall` 创建限定程序和 TCP 端口的入站规则，默认允许 `LocalSubnet`，适用于专用/域网络。需要限定客户端时，首次安装命令追加 `-AllowedClientAddress 'A的实际IP'`。不要关闭整个防火墙。

**每次重新运行首次安装脚本都会生成新凭据。查询配置、排查网络、更新已有 DLL 时，不要反复重装。**

### 4.4 保存连接信息

查看凭据：

```powershell
notepad.exe 'C:\Users\dfq\Desktop\BatteryConsole-Server-win64\access-key.txt'
```

凭据是本项目生成的密钥，不是 Windows 密码，也不是 Sysplorer 许可证。通过可信方式提供给 A 的操作人，不写进文档、普通日志或聊天。

`0.0.0.0` 是服务器监听全部 IPv4 网卡的配置值，不是 A 要填写的服务器地址。

## 6. A 端网络与 Qt 连接流程

### 6.1 使用 B 的当前 IP

B 最初的 `172.19.185.116` 已失效。本次重新执行 `ipconfig` 后，确认 B 当前为 `172.19.15.159`，网关为 `172.19.0.1`。

### 6.2 在 Qt 中连接

1. 在 A 启动已交付的 Qt 客户端。A 不需要安装 Sysplorer 或 SDK。

|---|---|

### 6.3 两端的模型与结果

A 的 EXE 和 B 的插件 DLL 各内嵌一份模型源码。A 用于取得预期 SHA-256，B 将自己的模型内容交给 Sysplorer 加载和求解。连接/任务建立及结果接收时核对模型标识；不会每个采样点重新计算整个模型源码哈希。

初始 SOC、电流等参数与模型源码哈希分开校验。修改源码需要更新配套模型资源；不能关闭哈希校验来连接不同模型。模型哈希一致也不能证明 SDK ABI、许可或编译器正常。

服务器生成结果，客户端下载并核验后保存；无需共享文件夹。B 的任务目录为 `C:\BatteryJobs\<任务UUID>`；A 的本地任务目录由客户端配置决定，在“状态信息”中查看。Sysplorer 原生窗口不自动镜像到 A。

## 8. 本次实际故障与解决方法

| 实际现象 | 已确认原因 | 处理方法 |
|---|---|---|
| `Sysplorer not found: ...2026a\Bin64\mworks.exe` | 使用了示例路径，B 实际安装的是 2026b | 正常打开目标实例，用 `Get-Process mworks` 查实际路径；将上两级目录传给 `-SysplorerHome` |
| 从 `C:\Windows\system32` 执行 `-File .\Install-Server.ps1`，提示文件不存在 | 先运行脚本，后切换目录；相对路径指向 System32 | 使用脚本绝对路径，或先 `Set-Location` 到包含脚本的目录，再执行 |
| 新开管理员窗口后原安装目录变量没有值 | PowerShell 变量只在原会话中存在 | 在新窗口重新赋值，或直接使用已核对的绝对路径；不要把空变量传给安装脚本 |
| `Check-Server` 找不到存活记录；进程存在但无 TCP 39001 监听、无远程状态目录 | 插件未成功启动服务，需继续查加载阶段 | 先核对进程、端口及状态记录，不直接归咎于防火墙或密钥 |
| DLL 哈希正确，但模块列表没有插件；诊断显示两个 `MISSING_EXPORTS` | 2026b 缺少旧插件静态导入的 `CreatePlotWin` 和 `IsRunning` 精确符号 | 用本次兼容补丁保留配置更新 DLL；不覆盖 Sysplorer 的 Qt/SDK DLL，也不单凭 Qt 小版本猜结论 |
| 诊断脚本 `Join-Path` 报 Path 为空，指向参数默认值中的 `$PSScriptRoot` | 该 PowerShell 环境在参数默认值求值阶段没有有效脚本目录 | 修正版在脚本正文解析路径；旧版可显式传入绝对 `-OutputFile` 绕过。错误发生时诊断尚未运行 |
| 固定的桌面补丁路径不存在 | 包实际解压到了 Downloads；桌面另有单独脚本 | 用限定在 Desktop/Downloads 的文件名搜索找到实际路径，选择有完整 DLL 和清单的目录 |
| 搜索找到两个 `Update-ServerPlugin.ps1`，自动流程停止 | 存在多个候选，不能安全地随便选一个 | 本次明确选择 Downloads 中的完整补丁包，再用绝对路径执行 |
| B 监听正常，但 A 访问 `172.19.185.116` 超时 | B 的地址已经变为 `172.19.15.159` | 重新在 B 执行 `ipconfig`，用新地址测试；新地址 TCP 建连已确认成功 |
| 同时出现一个 `169.254.*` 地址 | 另一网卡只有自动配置地址、没有本次可用网关 | 本次选择有明确 IPv4/网关且 A 能访问的“以太网”，不把该自动配置地址用于连接 |

两个旧静态入口点的完整名称是：

```text
mw_develop.dll:
?CreatePlotWin@MwPlotWindowManager@@QEAAPEAVMwSimPlotWindow@@_NH0@Z

mw_global.dll:
?IsRunning@MwTaskManager@@QEAA_NXZ
```

补丁不再静态依赖它们；任务检查在运行时匹配精确的非 const/const 签名，未知时拒绝执行；原生绘图属于可选功能，缺少匹配接口时保留导出与 Qt 回放。

## 9. 后续可能遇到的问题与排查顺序

本节为排查预案，**不是本次已发生故障的结论**。

| 现象 | 优先检查 |
|---|---|
| 端口监听失败 | 同端口是否已有其他进程/宿主；监听 IP 是否属于 B；配置和目录权限是否正常 |
| B 监听成功，A 的 TCP 测试失败 | B 当前 IP、A 到 B 的路由、网络隔离、防火墙规则的程序/端口/远端地址和专用/域配置文件是否匹配 |
| TCP 成功，但认证失败 | 两端凭据是否一致、是否不慎重跑安装脚本生成了新密钥；不要发送密钥到聊天 |
| 生命周期能力缺失或模型哈希不匹配 | 客户端和服务器包是否配套、是否打开了旧桌面副本、是否连到了其他宿主；保留校验并更新正确版本 |
| `HOST_TASK_STATUS_API_UNSUPPORTED` 或 `MISSING_RUNTIME_EXPORTS` | 运行补丁中的诊断脚本，记录实际 SDK 导出；需要针对准确接口适配或使用配套 SDK，不能假设宿主空闲 |
| 能加载但翻译失败 | 根据任务 `stage`、错误代码和 B 日志检查许可、编译环境、模型和英文可写目录；不要只重试网络 |
| 计算完成但结果下载失败 | A 的目录权限、剩余空间和网络；重试同一任务下载，不重新求解。下载完成前避免其他客户端替换宿主当前任务 |
| 运行中断线 | 保留原客户端进程并重连核对会话和任务；运行任务失联超过约 15 秒时服务器请求暂停，以恢复后的实际状态为准 |
| 宿主重启后旧任务无法恢复 | 新宿主会话不能接收旧任务控制；在 B 确认已有结果，再建立新任务，不自动重放“开始” |

排查顺序固定为：**进程和路径 → 插件加载/依赖 → 本机监听 → A/B 网络 → 认证/能力/模型 → SDK 加载与求解 → 结果传输**。上一步未通过时，先解决该层问题。

## 10. 日常运行、维护与证据保管

日常流程：B 启动 Sysplorer 并保持运行 → 核对 B 当前 IP → A 显式连接 → 操作仿真 → 等结果下载校验完成后再退出。

维护时遵守以下约定：

- 首次安装与已有 DLL 更新分开。更新前保存结果并关闭目标实例，保留原配置和凭据。
- DLL 哈希用于确认二进制版本和复制完整性；模型哈希用于确认模型内容；SDK 入口点及真实仿真仍需分别验证。
- 诊断脚本和远程状态 JSON 不读取访问密钥。不要上传 `access-key.txt`、完整 `remote.ini` 或含本机 UDP token 的发现 JSON。
- 当前通信具备认证和签名，但没有内容加密，使用受信任局域网或 VPN。
- 开发机回归、B 现场服务部署、A/B 连通与 2026b 求解验收分开记录，不把前一层通过写成后一层完成。
