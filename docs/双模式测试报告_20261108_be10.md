## 隔离回归和未解决问题

隔离整套回归为 **61 passed / 1 failed / 3 skipped**。3 个真实环境用例在隔离运行中按设计跳过，已由上面的真实验收另行覆盖。不得把隔离结果写成 62/0。

唯一失败是 closingClientSendsStop：客户端已 Running，销毁 Runner 后，模拟服务器仍 Running，未在断言等待期进入 Stopped。单独运行该用例 3/0；与 changedSessionDoesNotReplayStart 组合时出现过 3/1，最终重测亦有 4/0，说明存在时序相关性。实际根因尚未充分定位。

曾试验退出前刷新发送缓冲，但连续组合测试第 3 次仍失败，已撤回该产品改动；没有保留一个只让部分测试变绿的修补。最终产品 Runner 与基线一致，仅加强了测试中的运行状态断言。

当前处理建议：

1. 运行中先点击“停止”，等待 Stopped/Completed 等终态，再关闭客户端。
2. 失联后核对原任务，不重复开始；服务器既有失联暂停策略不能等同于关闭即停止的确认。
3. 后续应围绕关闭流程等待停止确认、有限超时、仍运行任务的恢复，以及会话更换后的传输时序修复并增加重复回归。当前不宣称此问题已解决。

## 本轮实际修正

PowerShell 7/.NET 会把通过 SetEnvironmentVariable 恢复的 null 字符串变成“存在但为空”的环境变量，影响精确环境保护及使用 qEnvironmentVariableIsSet 的模拟程序。本轮改为：原值不存在时 Remove-Item Env:，原值存在时恢复原字符串。

修正范围是 Start-LocalWorktree、Start-Remote、Start-RemoteChecked、Start-Sysplorer 和对应测试清理；没有改变网络协议、求解模型、界面布局或本机按需启动行为。PowerShell 5.1 和 7 的真实客户端入口回归均通过。

部署工具在当前树的模拟目录中验证通过：

- 服务器启动和子进程依赖路径：logs/remote-vm/server-path/test-c27bcaa73abe4653a1db947f82fe0af1/result.json。
- 插件备份、复制、哈希、幂等、坏清单拒绝、活动实例拒绝、配置与密钥字节及 ACL 保留：logs/connection-fix/update-01cf5486aa004265a42ccc72e498546a/result.json。
- 工作树路径、Junction、盘符保护：logs/local-worktree/paths-e3f1e7ab98c34e549ab53e25e14592b4/result.json。

模拟脚本最初串行运行曾因清理时留下空的 BATTERY_FIXTURE_SOLVER 而导致后一个模拟进程提前退出；同样按缺失/空字符串区别修正后，整组通过。这是测试环境污染，不是远端安装失败。
