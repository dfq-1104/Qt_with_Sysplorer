## 远程失败的原因与修正

本轮发现两个独立情况：

- 这台客户端电脑开启了 127.0.0.1:10090 系统代理。旧 TCP 套接字使用默认代理策略；模拟拒绝连接的代理可使同一配套服务在认证前连接失败。现在只将 Sysplorer 客户端套接字固定为 NoProxy，直接连接填写的 IP/端口。系统代理、VPN 和防火墙设置均未修改。[Qt 套接字代理接口说明](https://doc.qt.io/qt-6/qabstractsocket.html#setProxy)。
- 实时现场另有 TCP 超时。虚拟机的 Check-Server 返回当前用户/39001 没有 live 监听记录；这时还没进入访问凭据校验。用户使用原修复启动脚本启动后，确认 Listening=True，宿主机认证与真实仿真恢复通过。

代理对照使用本机非回环 IPv4 地址和完整认证协议：修正前 ConnectionFailed；修正后认证和 hello 成功，模拟代理的连接计数为 0。真实服务器恢复后，最终 EXE 的正确/错误凭据对照及真实全流程也通过。不能把“代理问题已修复”理解为远端无需启动服务。

## 尚未解决的退出边界

“关闭运行中的客户端后停止指令一定到达”仍存在时序失败。虽然整套回归本次通过，专门组合重测仍出现服务器保持 Running；证据为 logs/connection-repair-20261108/close-no-proxy/1.txt。它没有因代理修正而被稳定解决。

运行中先点击“停止”，确认结束后再关闭 Qt。不将关闭窗口作为可靠停止方式，也不将服务器失联后的暂停策略等同于任务已停止。本轮不能宣称所有边界问题均已解决。
