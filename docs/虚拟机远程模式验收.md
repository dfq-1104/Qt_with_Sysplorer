## 已定位并修复的插件问题

旧 2026b 兼容补丁去掉了 `IsRunning()` 静态导入，但仅尝试原非 const/const 两个动态签名，虚拟机两者均不支持，因此监听与认证正常仍不能完成 hello。

本次依据本机 SDK 的 `mw_task_manager.h`，增加精确的 `GetRunningThread()` 非 const/const 签名适配。返回非空指针即视为繁忙，不解引用、不读取对象布局；未知接口继续拒绝任务。原 `IsRunning()` 优先级和原有任务隔离保留。

hello 的模型哈希与能力字段现在独立于宿主就绪检查生成。若 SDK 仍不支持，响应保留 `ok=false`、`ready=false`，但可完成模型指纹检查，不能加载或求解。网络协议与客户端二进制不变。

补丁仅允许已确认前版 DLL `9DE7BBE8C49BB7344409C08B0650EC3182EEF7D3105CFAD4C14F2FC208D3C509` 和宿主 `26.8.0.2280`，未知版本拒绝覆盖。更新前检查目标实例全部退出，即使磁盘上已是新 DLL，也不能忽略仍加载旧 DLL 的进程。更新脚本备份旧文件、核对 SHA-256，保留原配置与凭据。具体用户操作见[远程插件任务接口补丁](远程插件任务接口补丁.md)。

2026-11-08 用户诊断已确认 2026b 导出 `?GetRunningThread@MwTaskManager@@QEAAPEAVMwThread@@XZ`，实际 hello、独立加载和翻译均已越过原任务状态检查。`nativePlotSupported=False` 表示旧原生绘图接口不适配，保留 Qt 结果显示；原生绘图在结果完成后调用，当前启动失败发生在它之前。

`Start-Sysplorer.ps1` 已加入同一安装的 `Bin64` 和 `Simulator\Bin64`，保留清理 Qt/Python 污染环境的行为，并在启动后恢复调用者环境。工作树内实际父子进程测试证明旧启动器的子程序无法加载只在父程序 Bin64 中的依赖，新启动器正常。PowerShell 7 与 Windows PowerShell 5.1 均通过，覆盖显式路径、原 deployment.json 复用、空格路径、配置字节/ACL 不变和调用者环境恢复。修复包及操作见[启动路径修复](远程求解器启动路径修复.md)。

