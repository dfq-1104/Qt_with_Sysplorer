普通双击与测试启动对比（2026-11-08，北京时间）

历史范围：R3 外部模型阶段。R5 已改用客户端内置模型，普通双击本机完整流程已通过；当前状态见“内置模型交付测试报告.md”。本文保留对照证据，不作为新版操作步骤。

结论
1. 已复现同一路径、同一 EXE 因启动来源不同而读到不同模型内容。
2. 未发现通过修改普通启动脚本即可修复的证据；直接普通双击原 EXE 同样失败。
3. 普通启动进程在未连接 Sysplorer 时就读到保护内容，因此“先连接再加载”不是出现此差异的必要条件。
4. 可以确认读取视图与启动来源有关，尚未读取或确认天喻具体信任/策略规则，不能断言是哪一条父进程规则。
5. 未修改天喻策略、进程权限、EXE、模型或插件，也未使用其他进程为客户端代读模型。

已排除的差异
- EXE：F14C8DAC456CDE9AA14E66B0E697FFFF4FC399DA5E2D06FC1C51F29AF5FDE7A2，完全相同。
- 程序及模型路径：均为当前 R3 包在 C 盘的真实路径，本轮对照未通过 Z 盘启动。
- 工作目录：均为当前 R3 客户端目录。
- Windows 用户：与观察进程相同；两个无参数长驻对照进程都在会话 3。
- 权限：两个长驻对照进程均未提权，完整性 RID 8192（中等），ElevationType=3。
- Qt：Core/Gui/Widgets/Network 和 qwindows 均来自当前包，版本及 SHA-256 一致。
- 天喻模块：稳定运行后两个进程均加载相同版本及哈希的 TyEnc64.dll、intefsctrl64.dll；刚启动时尚未加载不作为持久差异结论。
- 特殊诊断参数：测试启动的无参数、可见普通界面也读到正常模型；不是仅 --verify-custom 才能读取。
- PowerShell 版本/启动脚本：测试上下文调用原 Windows PowerShell 5 启动脚本，仍读取正常模型；普通双击同脚本读取保护内容。
- 模型包：诊断进程读取 ZIP 模型条目为 14000 字节、SHA-256 e03bd363…。

实测矩阵
A. 测试上下文 -> pwsh -> 原路径 EXE，无参数、可见界面、存活数分钟后加载：14000 字节，e03bd363…，UTF-8 校验通过。为避免意外操作真实宿主，该组指定不存在的宿主，校验后按预期报告 HOST_NOT_FOUND。
B. 测试上下文 -> Windows PowerShell 5 -> 原 Start-Client.ps1 -SmokeTest：未连接，模型哈希 e03bd363…。
C. 用户普通双击 Start-Client.cmd，长驻窗口 PID 24076 -> 连接 -> 加载：18096 字节，f9fc71eb…，文件起始 cbd5d6ddcdacd4aa（GBK 为“苏州同元”）。
D. 用户普通双击 Check-Startup-BeforeConnect.cmd -> 同一原启动脚本 -SmokeTest：Idle、未连接、无任务，模型哈希 f9fc71eb…，与 C 相同。该组只采样哈希，未直接采样字节数。
E. 用户从 Explorer 直接普通双击原 EXE，无参数 -> 连接 -> 加载：同样为 18096 字节、f9fc71eb…；父进程确认为 Explorer，仍未提权。
