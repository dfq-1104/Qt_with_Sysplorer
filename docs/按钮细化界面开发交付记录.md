## 1 最终按钮行为

| 入口 | 执行内容 | 成功后的状态 |
|---|---|---|
| 加载模型 | 检查配套能力、模型哈希及宿主空闲状态，只加载并确认固定电池模型 | 模型已加载，等待翻译；不写参、不翻译、不求解 |
| 翻译模型 | 必要时加载模型，已加载且有效时复用；读取当前输入、校验、写参、逐项回读、检查目录、翻译 | 准备就绪，等待开始；不自动求解 |
| 开始仿真 | 有有效准备实例且输入相同时直接启动；否则自动完成必要的加载、写参回读和翻译，再启动 | 以真实宿主控制器确认更新运行状态 |

用户可以直接点击“开始仿真”，无须先点击保存、加载或翻译。修改参数后开始入口会重新准备；原文档“参数修改后禁用开始，必须手动翻译”的规则由这一追加要求替代。准备、启动和控制请求尚未确认时，相关按钮仍禁用，避免重复提交。

已准备后修改输入再点击翻译或开始，先等待旧准备实例的 `discard` 确认，再读取当前输入建立新任务。保存相同数值不会无故废弃准备实例。停止或结束后的任务不被当作暂停任务继续运行。

## 2 已实现的界面功能

- 应用名称及图标保留在 Windows 标题栏；按钮上方的重复标题已按追加要求删除。
- 紧凑工具栏依次显示加载、翻译、开始、暂停或继续、停止、仿真倍速及时间；采用有序换行布局。
- 状态信息移到工具栏下方，阶段日志放到底部。两处独立折叠，首次默认收起，通过 `QSettings` 保存选择，状态和样本刷新不重建折叠控件。
- 阶段日志提供分类、复制和打开任务目录。目录存在时才允许打开；收起状态和日志不停止记录。启动失败仍弹出非阻塞警告，操作失败摘要保持直接可见。
- 取消底部常驻提示行。参数与任务详情移入可收起状态信息。
- 保留电池和结果曲线页，主视图区占用整行宽度；同时保留本工作树已有的“运行中调参”页及其业务功能。
- 结果页增加独立的回放所选结果、暂停或继续回放、停止回放、回放倍速、时间与状态。真实仿真按钮只操作宿主，本地回放按钮只操作播放器。
- 修正旧逻辑中“切换结果后仍回放最近一次结果”的问题，回放使用下拉框当前选择。失败任务保留既有结果，并恢复此前所选历史结果。
- “应用参数”更名为“保存参数”，保存客户端设置并更新预览；电压、电流、方向和起始电量可随重新打开恢复。翻译及开始仍重新读取实际输入。
- 固定回放时间标签的必要宽度，避免完整时间字符串刚更新时裁切；参数区保留简洁标题，详细说明放入悬停提示，避免窄窗裁切冗长文字。

## 3 接口与日志变化

协议仍为 `battery-udp/1`、`schema=1`，新增 `modelLifecycle=true` 能力、独立 `load` 和 `translate` 命令。`begin` 保留为旧准备接口。新客户端拒绝缺少能力或模型哈希不匹配的插件，不把独立加载降级为整条准备链路。

`load` 完成后返回 `Loaded`，参数回读快照仍为空。`translate` 在本宿主中复用有效模型；缓存类已不存在时重新加载。每次加载或翻译使用独立任务 UUID，沿用请求 ID 去重及客户端归属检查。`start` 仍只接受 `Prepared`，界面的自动流程负责补齐其前置步骤。启动时传递当前仿真倍速，插件等待控制器进入运行状态后才记录 `started`。

宿主状态新增 `stage` 字段，区分加载模型、写入参数、回读参数、检查输出目录、翻译模型、启动仿真、运行仿真与结果处理。写参与回读错误记录失败字段、期望值和实际值。错误不会因为来自“开始仿真”入口，就被统一改写成求解失败。

日志保留时间、任务编号、操作、阶段、错误代码和原始消息。启动失败保存到 `startup/<客户端编号>/client.log`；请求工作目录本身非法或不可创建时，使用临时诊断目录保存失败记录。请求令牌不进入新增普通日志。既有完整及部分结果的导出、任务归属、模型、参数、哈希和样本校验继续由原有真实链路完成。

完整协议说明见 [UDP任务协议](UDP任务协议.md)。

## 5 过程问题与处理

| 问题 | 处理及结果 |
|---|---|
| 旧 `begin` 串联加载、写参和翻译，无法支撑单独加载按钮 | 新增独立加载命令，翻译保留加载前置能力并复用模型；不把两个按钮连接到相同完整流程 |
| 仿真与回放共用暂停、停止、倍速及时间 | 分离两套控件和连接，并按真实宿主状态或本地播放器状态分别启用 |
| 未保存的参数不能直接翻译，保存相同值也会丢失准备实例 | 翻译读取当前输入，准备参数按数值比较；开始入口自动补齐准备 |
| 初始化阶段插件已绑定但宿主仍未就绪，被误判为占用并重复启动 | 继续等待原实例，不重新启动计时；发现、等待统一使用同一超时配置 |
| 测试宿主出现原生编译进程创建失败，宿主输出错误码 1 | 保留原始失败记录；缩短专用宿主及其唯一工作目录，并补齐输出目录检查。不能仅凭错误码认定唯一根因 |
| 失败后的旧逻辑优先恢复完整结果，可能改变此前所选部分结果 | 记录准备前的选择，失败后恢复相同结果；保留本次错误与旧有效数据 |
| 回放时间文字更新后可能超出初始标签宽度 | 为时间标签保留必要宽度，并在布局稳定后检查完整字符串宽度 |
| QtTest 文件日志被宿主子进程继承，PowerShell 等待进程树导致测试脚本不退出 | 改为等待测试进程本身，通过标准输出保存测试报告；每项结束另写立即关闭的 JSONL 记录 |
| 沙箱内构建工具无法启动 `cl` | 放行当前工作树的构建工具后完成 Qt、插件和测试编译；未更改系统编译配置 |

## 7 运行与复验

本工作树已生成配套运行包 `app/ui/runtime_buttons`。双击 [run_ui.bat](../app/ui/run_ui.bat) 或 [run_button_details.bat](../app/ui/run_button_details.bat) 启动。运行包配置指向本轮专用宿主，安装目录与其他工作树的包没有更新。

重建与复验命令在本工作树根目录执行：

```powershell
cmd /c app\ui\build.cmd
cmd /c tools\sysplorer_udp_plugin\build.cmd
cmd /c app\ui\tests\build.cmd
& app\ui\tests\run_button_details.ps1 -TestHost "$env:TEMP\BB0cf2"
& app\ui\deploy.ps1 -RuntimeDirectory app/ui/runtime_buttons -SysplorerHome "$env:TEMP\BB0cf2"
```

插件更换只应对空闲专用实例进行，先退出使用旧插件的该实例，再更新其 DLL 并重新启动。不能覆盖其他会话正在使用的插件。运行包的 `Host/TimeoutMs=180000` 用于本机较慢的首次初始化；默认值为 90000，环境变量 `BATTERY_HOST_TIMEOUT_MS` 可覆盖。

## 8 使用边界

- 新客户端需要本轮配套插件；临时专用宿主目录被清理后，需要按现有隔离宿主脚本重新准备并重新部署运行包。
- 结果仍按原有实现保存在当前客户端进程中，关闭后不自动重建历史结果列表；任务文件继续留在磁盘。
- 本轮验收范围为按钮与界面流程，以及相关真实链路回归。长时间丢包、翻译超时后的完整通信恢复、宿主中途重启、多客户端压力、不同 DPI 与其他 Sysplorer 版本仍需专项验收；不能将本轮正常链路通过等同于这些项目全部通过。
- 原有超时失败处理尚未全面升级为原流程文档设想的后台任务恢复状态机；通信异常后应先核对宿主实际任务状态再重新操作。
