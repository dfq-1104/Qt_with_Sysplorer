# 远程求解器启动路径修复（2026-11-08）

## 已确认原因

当前虚拟机的模型、认证和插件接口均已对齐，加载、翻译成功。启动求解失败的现场对照结果：

| 同一求解器、模型和工作目录 | 结果 |
|---|---|
| PATH 仅含原 GCC 4.9.4、Simulator\Bin64 和原系统项 | `-1073741515 / 0xC0000135`，即 `STATUS_DLL_NOT_FOUND` |
| 上述 PATH 只增加 Sysplorer 2026b\Bin64 | 正常完成 0 至 6 秒仿真，退出码 0 |

因此已证明求解器启动缺少运行依赖的搜索目录。现有静态诊断只检查生成的模型 DLL 直接导入，不能覆盖求解器 EXE 的完整依赖链；“未发现缺少直接导入”不等于运行时可加载。当前证据未锁定具体缺少哪一个 DLL，不能据此要求安装某个运行库。

旧 `Start-Sysplorer.ps1` 用绝对路径启动 mworks.exe，但没有为它及求解器子进程补充运行目录。新脚本将同一安装的 `Bin64`、`Simulator\Bin64` 放到该进程继承的 PATH 前部。启动后恢复调用终端的原环境，不更改系统或用户的永久 PATH，不混用其他安装的 DLL。

本包不含 DLL、安装脚本或凭据；不修改模型、Qt、插件、端口、防火墙和 remote.ini，也不结束已有进程。

## 虚拟机按顺序操作

1. 将宿主机工作树 `dist/remote-vm/BatteryConsole-Server-LaunchFix.zip` 复制到虚拟机，解压到 `C:\Users\dfq\Downloads`。确认 `BatteryConsole-Server-LaunchFix` 目录内有新版 `Start-Sysplorer.ps1`、清单和本说明。
2. 保存工作，手动关闭目标安装目录下全部 Sysplorer 实例。已启动进程不能通过后改 PATH 获得新环境，必须由新脚本重新启动。无需重新安装插件。
3. 在虚拟机日常运行 Sysplorer 的账号下执行，不需要管理员权限：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\Users\dfq\Downloads\BatteryConsole-Server-LaunchFix\Start-Sysplorer.ps1' -SysplorerHome 'C:\Program Files\MWORKS\Sysplorer 2026b' -Workspace 'C:\BatteryJobs'
```

4. 等主窗口初始化完成，使用原服务器包只检查监听：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\Users\dfq\Desktop\BatteryConsole-Server-win64\Check-Server.ps1' -Port 39001
```

5. 确认 `Listening=True`，告知宿主机操作人“已用新启动脚本重启”，再从宿主机进行模型预检和真实远程任务测试。PID 变化是正常现象。

本次使用的任务目录和安装目录已由现场确认；其他电脑改成其实际路径。不要重跑 `Install-Server.ps1` 或覆盖 remote.ini。桌面原服务器包中的旧启动脚本尚未自动替换，之后继续使用上面的新入口，避免再次以旧环境启动。

如果要保留桌面原入口，由用户先备份原 `Start-Sysplorer.ps1` 再仅替换该脚本，其余文件保持不变。新版在原服务器包内仍能读取已有 `deployment.json`，无需重复指定安装与任务目录。
