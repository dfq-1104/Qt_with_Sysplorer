# 两台电脑远程部署：按顺序操作

**本次 B 为 Sysplorer 2026b 的现场部署，请优先阅读[远程部署实操与故障处理_2026b](远程部署实操与故障处理_2026b.md)。** B 已安装 `9DE7…` 兼容插件，监听 TCP 39001，A 已成功连接其当前地址 `172.19.15.159`；Qt 认证和模型求解仍待验收。下面的 2026a 专项同步流程不得用于把已修复的 B 回退到旧 `9C187…` DLL。

本流程先在远端电脑安装并启动 Sysplorer 插件，再在操作电脑连接 Qt。使用已经提供的部署包，不需要在两台电脑重新编译源码。

本轮修复的两端包位于工作树 `dist/connection-fix/`，与已有 `dist/remote/` 中的其他版本分开放置。

后续本机专项已补充目标 PID、宿主路径和插件位置诊断，客户端附带 `Check-Local.ps1`。本机模型加载原理和具体纠错步骤见客户端包中的《本机运行说明》；该专项只验证本机模式，不能据此追加远程验证结论。

## 先选择：首次安装，还是只更新插件

- **从未部署远程插件**：从下文“第 1 步”开始，按顺序配置 B 的插件、端口和访问凭据，再连接 A。
- **已经配置好端口和凭据，只因旧插件连接失败**：执行下面的“仅更新插件”流程。不要重新运行 `Install-Server.ps1`，该首次安装脚本会生成新凭据。

### 仅更新插件：保留现有端口和访问凭据

本轮 Sysplorer 2026a 服务器包使用原配套 DLL，SHA-256 为：

```text
9C187D822403DFEDAAC606EC97CBB06346027E846FA6C8B86D1DE80271E85F9A
```

1. 在两端保存工作和结果，退出旧 Qt；在运行 Sysplorer 的电脑上，手动关闭**该安装目录下的所有 Sysplorer 实例**。更新脚本不会替你关闭程序。
2. 解压新的 `BatteryConsole-Server-win64.zip` 到一个可写的英文目录，例如 `C:\BatteryDeploy\BatteryConsole-Server-win64`。不要覆盖原有 `access-key.txt` 或丢弃原凭据记录。
3. 在运行 Sysplorer 的电脑上打开管理员 PowerShell，进入**新服务器包**目录后执行：

```powershell
Set-Location 'C:\BatteryDeploy\BatteryConsole-Server-win64'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Update-Plugin.ps1 -SysplorerHome 'C:\Program Files\MWORKS\Sysplorer 2026a'
```

`-SysplorerHome` 默认就是上述 2026a 路径；安装位置不同时必须填写实际路径。本机模式也在本机使用同一命令更新插件。受保护的安装目录需要管理员权限，脚本不自动提权。

4. 确认脚本输出 `Plugin ready` 和上述完整哈希。脚本先检查目标是否退出，再把旧 DLL 备份到新服务器包的 `versions\旧SHA256.dll`，更新 DLL 并复核哈希，写入 `update-report.json`；失败会尝试恢复备份。重复执行同版本不会重写 DLL。它不修改 `remote.ini`、密钥文件、端口和防火墙。
5. 手动启动一个目标 Sysplorer，等待初始化。远程部署继续使用原来的 IP、端口和凭据；首次安装后的日常运行只需启动 Sysplorer，插件会随宿主加载。
6. 在操作电脑解压新版客户端包到新目录，运行 `Start-Client.ps1`。旧桌面副本不会自动替换。打开 Qt 后保持未连接，点击“连接设置 → 保存并连接”；远程填写原服务器信息，本机选择“本机”。
7. 确认状态进入“已连接”，再依次验证加载、翻译、开始。客户端会同时检查 `modelLifecycle=true`、`splitLifecycle=true` 和模型哈希；只有三项均通过才继续。客户端期望模型哈希为 `e03bd3634004ca82bb190521c214ec5fae25713120db83caf016aeac8b7472cd`。

如果仍显示“连接失败”，展开错误与分阶段日志查看具体原因。兼容性错误会完整列出缺失能力及期望/实际模型哈希，并立即结束本次尝试；不会反复握手或再启动实例绕过版本检查。本机修复后可重新点击连接、加载、翻译或开始；远程使用“重连并核对”或连接设置重试，始终保持远程模式。已运行任务的断线恢复、下载重试以及历史有效结果仍按原流程处理。

若需回退，先退出目标 Sysplorer，再手动恢复 `versions` 中对应旧 DLL，并使用与之配套的客户端；配置与凭据无需恢复，因为本流程没有改动它们。不要使用降低哈希/能力校验的方式连接旧插件。

已部署旧插件且在 Sysplorer 2026b 上诊断出 `CreatePlotWin` / `MwTaskManager::IsRunning` 缺失入口点时，使用《2026b插件加载修复说明》中的 DLL 定向更新流程，保留端口和密钥。不要通过反复执行首次安装脚本处理这个问题。该补丁修复已确认的加载阻塞，2026b 的其余接口和求解仍需现场验证。

**本版启动策略：打开 Qt 只读取配置、显示界面，不自动连接或启动 Sysplorer。本机模式在点击“连接设置 → 保存并连接”，或加载、翻译、开始时按需发现/启动；远程模式只连接配置的地址，失败不转成本机。**

本机首次按需启动可能较慢，界面会等待宿主初始化完成。默认宿主就绪等待为 180 秒；需要调整时，在客户端 `sysplorer.ini` 的 `[Host]` 下设置 `TimeoutMs=180000`（单位毫秒），或使用 `BATTERY_HOST_TIMEOUT_MS`。该设置不会让 Qt 在打开时自动启动宿主。

- **远端电脑 B**：安装 Sysplorer、插件、可用许可和模型翻译所需的编译环境，负责计算。
- **操作电脑 A**：运行 Qt 界面，负责发指令、看曲线和保存结果；远程模式不要求安装 Sysplorer、SDK 或编译器。

以下按受信任的同一局域网或已经互通的 VPN 操作。示例中 B 的地址为 `192.168.1.20`、服务端口为 **TCP 39001**。请用你的实际地址替换示例地址。

## 第 1 步：在远端 B 准备 Sysplorer 和服务器包

**这一节所有操作都在远端电脑 B 上进行。**

1. 确认 B 已安装配套的 **Sysplorer 2026a**，许可正常，模型可以正常翻译、运行。
2. 保存工作并关闭准备安装插件的 Sysplorer 实例。安装时不要让该实例运行。
3. 将 `BatteryConsole-Server-win64.zip` 复制到 B 并解压。不要直接在压缩包里运行脚本。
4. 找到包含 `Install-Server.ps1` 的文件夹。以下假设实际路径为：

```text
C:\BatteryDeploy\BatteryConsole-Server-win64\
  battery_udp_control.dll
  Install-Server.ps1
  Update-Plugin.ps1
  Start-Sysplorer.ps1
  Check-Server.ps1
  Diagnose-Server.ps1
  remote.ini.example
  部署说明.md
  验证记录.md
  manifest.json
```

如果解压时多套了一层目录，以能看到 `Install-Server.ps1` 的那一层为准。

本流程假设 Sysplorer 安装目录是：

```text
C:\Program Files\MWORKS\Sysplorer 2026a
```

如果你的安装位置不同，后续安装命令中的 `-SysplorerHome` 必须改成实际目录。该目录下应能找到 `Bin64\mworks.exe`。Sysplorer 安装路径和仿真任务目录使用英文路径。

## 第 2 步：在 B 记录服务器 IP 和日常运行账号

在 B 打开一个普通 PowerShell，依次执行：

```powershell
ipconfig
whoami
```

记录两项信息：

| 信息 | 在哪里看 | 示例 |
|---|---|---|
| B 的 IPv4 地址 | 正在使用的以太网或 Wi-Fi 网卡下的“IPv4 地址” | `192.168.1.20` |
| 运行 Sysplorer 的 Windows 账号 | `whoami` 的输出 | `SIM-PC\operator` |

选择 A 能访问到的网卡地址。**不要把 `127.0.0.1` 或 `0.0.0.0` 当作另一台电脑的连接目标。** `127.0.0.1` 指当前电脑；`0.0.0.0` 仅用于服务器监听配置。

建议由网络管理员为 B 保留稳定地址。IP 改变后，A 的连接地址也要更新。

## 第 3 步：在 B 一次完成插件、端口、凭据和防火墙配置

右键开始菜单，打开**管理员 PowerShell**或管理员终端中的 PowerShell。

先进入第 1 步找到的服务器包目录：

```powershell
Set-Location 'C:\BatteryDeploy\BatteryConsole-Server-win64'
```

再执行下面这条完整命令。它将安装插件、监听 TCP 39001、生成访问凭据，并创建允许同一子网访问的防火墙规则：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Server.ps1 -SysplorerHome 'C:\Program Files\MWORKS\Sysplorer 2026a' -ListenAddress '0.0.0.0' -Port 39001 -Workspace 'C:\BatteryJobs' -OpenFirewall
```

安装前检查参数含义：

| 参数 | 作用 | 你需要修改吗 |
|---|---|---|
| `-SysplorerHome` | B 上 Sysplorer 的安装目录 | 安装位置不同时修改 |
| `-ListenAddress '0.0.0.0'` | 监听 B 的所有 IPv4 网卡 | 初次按此配置即可；也可以限定为 B 的某个固定 IP |
| `-Port 39001` | TCP 服务端口 | 未被占用时使用 39001；更换后 A 也要填写新端口 |
| `-Workspace 'C:\BatteryJobs'` | B 保存仿真任务和结果的位置 | 可换成有空间的英文目录 |
| `-OpenFirewall` | 创建相应 TCP 入站规则 | 本流程保留此参数 |

这条命令默认放行 `LocalSubnet`，即本机所在子网。若单位要求只允许某一台 A 访问，在**首次执行时**使用下面这个完整版本，替换其中 A 的实际 IP；它与上面的命令二选一：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Server.ps1 -SysplorerHome 'C:\Program Files\MWORKS\Sysplorer 2026a' -ListenAddress '0.0.0.0' -Port 39001 -Workspace 'C:\BatteryJobs' -OpenFirewall -AllowedClientAddress '192.168.1.10'
```

如果管理员终端使用的账号与第 2 步记录的日常运行账号不同，请在选定的安装命令末尾增加 `-ServerUser 'SIM-PC\operator'`，并替换成实际账号。这样日常用户才能读取配置和访问任务目录。若只是同一账号通过 UAC 提权，不需要额外指定。

防火墙规则适用于 Windows 的**专用/域网络**，不适用于公用网络。可运行 `Get-NetConnectionProfile` 查看 B 当前网卡的 `NetworkCategory`。若是公用网络，请按实际网络可信程度和单位管理要求配置网络/防火墙，不要关闭整个防火墙。

如果命令出现红色错误，先处理错误，暂时不要执行下一步。常见原因是 Sysplorer 仍在运行、安装路径填错、终端没有管理员权限或目录不可写。

**这一步只做首次安装或升级。不要为了查看 IP、端口或凭据再次运行安装命令；每次运行都会生成新凭据。**

## 第 4 步：在 B 确认插件位置、端口并取得访问凭据

安装成功后，应看到类似输出：

```text
Installed plugin: ...\Bin64\addins\BatteryUdpControl\battery_udp_control.dll
Remote configuration: ...\Bin64\addins\BatteryUdpControl\remote.ini
Access key saved privately to: ...\access-key.txt
```

检查实际安装文件：

```text
C:\Program Files\MWORKS\Sysplorer 2026a\Bin64\addins\BatteryUdpControl\
  battery_udp_control.dll
  remote.ini
```

`remote.ini` 已由安装脚本生成并启用远程监听，不需要手工复制 `remote.ini.example`。其中的配置大致如下，**下列只用于解释，不要把占位值覆盖到真实配置中**：

```ini
[Remote]
Enabled=true
ListenAddress=0.0.0.0
Port=39001
Workspace=C:/BatteryJobs
AccessKey=<安装脚本自动生成的64个十六进制字符>
```

接下来，在服务器包目录打开生成的凭据文件：

```powershell
notepad.exe .\access-key.txt
```

文件中只有一段 64 字符的密钥。请通过你信任的方式把它提供给 A 的操作人，后面填入 Qt 的“访问凭据”。不要附带多余空格，也不要放到公共共享目录、日志或截图里。

访问凭据由本项目安装脚本生成，**不是 Windows 登录密码，也不是 Sysplorer 许可证**。配置文件和凭据文件的权限限制为指定运行用户、Administrators 和 SYSTEM；若提示无权读取，请用第 2、3 步中指定的用户或管理员操作，不要删除权限保护。

此时应已准备好 A 将使用的三项信息：

```text
B 的实际 IP：例如 192.168.1.20
TCP 端口：39001
访问凭据：access-key.txt 的完整内容
```

## 第 5 步：在 B 启动 Sysplorer

回到日常运行 Sysplorer 的 Windows 账号。首次建议在服务器包目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Sysplorer.ps1
```

它会读取安装记录，启动正确的 Sysplorer，并使用英文工作目录。该脚本只是辅助启动 Sysplorer，不是另一个需要常驻的远程服务。

也可以正常双击启动已安装插件的 Sysplorer。插件会随宿主自动加载和监听，无需再运行 Qt 客户端、Python 或额外的服务程序。

等待 Sysplorer 打开并完成初始化；如果有许可或编译环境对话框，先处理。**保持 Sysplorer 运行。** 本项目的固定模型可由 Qt 后续发出加载指令，通常无需在 B 手动打开模型。

## 第 6 步：在 B 确认远程端口已监听

在**运行 Sysplorer 的同一 Windows 用户**下，进入服务器包目录，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Check-Server.ps1 -Port 39001
```

应看到：

```text
Enabled   : True
Listening : True
Address   : 0.0.0.0
Port      : 39001
LastError :
```

还会列出 `mworks` PID 和状态文件路径。只有 `Listening=True` 才表示服务已经成功监听。

如果不符合预期：

- 找不到记录：确认 Sysplorer 已启动、插件安装在正确的宿主中，并且检查命令与宿主使用同一 Windows 用户。
- `Listening=False`：查看 `LastError`，常见原因是端口被其他进程或另一个 Sysplorer 实例占用，或者监听 IP 不属于 B。
- `AUTH_FAILED`：表示最近一次客户端认证失败；监听可能仍正常，后续应核对两端凭据。成功认证会清除此错误。

先让 B 的检查通过，再到 A 操作。一个指定端口只对应一个宿主实例，初次部署只启动一个远程 Sysplorer。

## 第 7 步：在 Qt 操作端 A 解压客户端包

**从这里开始的操作都在电脑 A 上进行。**

1. 将 `BatteryConsole-Client-win64.zip` 复制到 A 并解压。
2. 保留整个目录，不能只复制 EXE。目录中应有 `battery_console_ui.exe`、Qt/VC++ DLL、`platforms`、`qt.conf` 和 `sysplorer.ini` 等。
3. A 不需要安装 Sysplorer、SDK 或模型编译器，也不需要安装服务器包里的插件。

以下假设客户端解压目录为：

```text
C:\BatteryDeploy\BatteryConsole-Client-win64
```

## 第 8 步：先在 A 检查能否访问 B 的端口

在 A 打开普通 PowerShell，执行，记得替换为第 2 步记录的 B 的真实 IP：

```powershell
Test-NetConnection -ComputerName 192.168.1.20 -Port 39001
```

应看到：

```text
TcpTestSucceeded : True
```

这表示 TCP 端口可以访问，**尚未验证访问凭据或模型版本**。即使 `PingSucceeded=False`，只要 TCP 检查为 True，也可以继续。

如果 `TcpTestSucceeded=False`，先检查：B 是否还在运行 Sysplorer、B 第 6 步是否监听成功、IP/端口是否填错、两台电脑的网络是否互通，以及防火墙规则是否适用于当前网卡配置文件和 A 的地址。此时先不要反复更换访问凭据。

A 不需要配置自己的固定 TCP 入站端口。

## 第 9 步：在 A 打开 Qt 并填写连接设置

1. 双击客户端目录中的 `battery_console_ui.exe`。
2. 初次默认是本机模式，显示“未连接”。打开界面不会启动本机 Sysplorer，也不会因为 A 没有安装 Sysplorer 弹出启动错误；A 走远程模式不需要补装 Sysplorer。
3. 点击主窗口新增的 **“连接设置”**。
4. 按下表填写：

| 界面项目 | 填写内容 |
|---|---|
| 连接方式 | `远程 · IP 与端口` |
| 服务器地址 | B 的实际 IP，例如 `192.168.1.20`；不是 A 的 IP，不是 `0.0.0.0` |
| TCP 端口 | B 安装时配置的端口，默认 `39001` |
| 访问凭据 | 第 4 步 `access-key.txt` 中的完整密钥；首次连接必须填写 |

5. 点击 **“保存并连接”**。
6. 等待网络认证、协议能力、模型版本和宿主占用检查完成。

正常情况下，连接条会显示类似：

```text
远程 192.168.1.20:39001 · 已认证连接
```

展开“状态信息”应看到 Sysplorer 已连接，加载/翻译/开始按钮可用。只有认证连接字样而按钮尚未可用时，继续看状态信息是否正在初始化、版本不匹配或宿主被占用。

如果连接后立即断开，核对密钥是否完整、B 是否重新运行过安装脚本，以及两端是否使用配套部署包。TCP 端口检查通过也不能替代这些检查。

Qt 会保存连接方式、地址、端口和经过 Windows 当前用户保护的凭据。下次打开 Qt 仍然保持未连接；点击“连接设置 → 保存并连接”才发起连接，同一 Windows 用户的“访问凭据”留空可复用已保存值。换服务器或重新安装生成新密钥后，需要重新填写。连接失败会保留远程模式，不会自动启动本机 Sysplorer。

## 第 10 步：在 A 做第一次仿真确认

1. 在电池页填写本次参数。
2. 可以依次点击“加载模型”→“翻译模型”→“开始仿真”；也可以直接点击“开始仿真”，由程序补齐必要的准备步骤。
3. 观察仿真时间和实时电池/曲线是否更新。
4. 需要时测试暂停、继续和停止，等待服务器确认状态。
5. 自然结束或主动停止后，等待结果下载和校验完成，再使用结果页回放。

计算在 B 完成，校验后的结果下载到 A 保存。不需要设置两台电脑的共享文件夹，也不要求两端路径相同。B 上的 Sysplorer 原生窗口不会自动镜像到 A。

部署完成后，日常只需：**B 启动 Sysplorer 并保持运行 → A 启动 Qt 并连接 → A 操作仿真**。通常不必再次运行安装命令。

需要留存部署信息时，记录 B 的 IP、端口、Sysplorer 目录和运行账号即可；访问凭据另外安全保管。服务器任务目录默认 `C:\BatteryJobs`，A 的本地任务目录可在“状态信息”中查看。

## 附录 A：日常操作与结果位置

日常顺序为：B 启动 Sysplorer → A 启动 Qt 并连接 → A 操作仿真。

远程模式不会在 A 自动启动 Sysplorer，也不会在连接失败时切换成本机求解。加载/翻译由 B 的插件调用本地 SDK；本项目固定模型随配套插件提供，通常不需要在 B 上手动打开模型。

结果文件先在 B 的任务目录生成，然后分块下载到 A：

| 文件/目录 | 位置与含义 |
|---|---|
| B 的任务目录 | `Workspace/<任务UUID>`：宿主日志、CSV、结果清单、原生求解产物 |
| A 的任务目录 | 默认 `%TEMP%/BatteryConsoleUDP/<任务UUID>`；也可用 `BATTERY_SIM_WORKSPACE` 指定 |
| A 的 `client.log` | 客户端请求和阶段记录，不记录密钥和认证报文 |
| A 的 `result.csv/result.json` | 下载后再次检查任务、模型、参数、哈希、点数和数据范围，核验成功后用于回放 |

两端目录可以完全不同，不依赖共享磁盘。远程客户端允许本地结果目录包含中文；宿主模型编译工作目录仍要求英文。界面中的“打开任务目录”打开 A 的本地目录；服务器目录可通过日志诊断信息和 B 的文件系统查看。

暂停和调参控制的是 B 的真实任务。结果回放读取 A 已保存的结果，不重新请求求解。Sysplorer 原生窗口/曲线位于 B，不会镜像到 A。

## 附录 B：断线、下载失败与退出

- **网络中断**：保留最后采样，不把未知状态宣称为计算失败，也不重开任务。点击“重连并核对”。
- **服务器失联暂停**：现有宿主逻辑在运行任务超过约 15 秒未收到所属客户端请求时请求暂停；不是立即强制停止。恢复连接后以宿主返回的实际状态为准。
- **重连**：仅当原客户端进程仍在、服务器会话未变，才恢复原任务；待确认请求沿用原编号，服务器去重。
- **宿主重启**：新会话不会接受旧任务控制。客户端报告会话变化，需在 B 确认原结果后再开始新任务。
- **结果下载失败**：计算与下载分开。点击“重试下载”重新获取同一任务的 CSV 和清单，不重新仿真；下载过程不更换任务编号。
- **下载期间保留宿主任务**：避免其他客户端在该宿主启动新任务；当前结果接口面向宿主保留的当前任务，不提供历史任务下载服务。
- **结束跟踪**：仅在断线或下载失败时提供。释放客户端本次跟踪，不强制停止服务器任务；之后不能通过原客户端流程继续接管该任务。
- **正常退出 Qt**：对本进程拥有的活动任务尽力发送停止，准备实例发送释放；最终结果未必能在退出前下载。应先停止并确认结果保存。
- **退出 Sysplorer**：远程服务随宿主关闭。第一版不支持远程启动已关闭的 Sysplorer、客户端重启后的任务接管或宿主重启后的求解恢复。

已验证历史结果保持原来的进程内列表机制；重新启动客户端不会自动扫描磁盘重建历史列表。原始文件仍可保留在任务目录。

## 附录 C：本机模式与更新/回退

切换到“本机”后继续使用回环 UDP、发现文件、PID 校验和按需启动逻辑。打开 Qt 不执行这些连接动作；点击“连接设置 → 保存并连接”，或直接点击加载、翻译、开始，才寻找本机实例，未找到空闲实例时再尝试启动。需在当前电脑提前安装 Sysplorer 和配套插件。插件远程监听默认关闭，缺少 `remote.ini` 时不会对网络开放端口。

源码启动入口 `app/ui/run_ui.bat → start_ui.ps1` 也只启动 Qt，不再自动安装/同步本机插件；本轮优先打开当前 `dist/connection-fix` 的客户端包，缺少时才寻找 `dist/remote`，可用 `-RuntimeDirectory` 指定其他运行目录。更换版本后应关闭旧 Qt 并从新包启动，旧目录中的 EXE 不会被自动更新。

如需首次用服务器安装包部署纯本机插件，可在安装时增加 `-DisableRemote`。不需要防火墙规则。已有安装只更新 DLL 时，使用本文开头的 `Update-Plugin.ps1` 流程。

更新前停止任务、确认结果已保存并关闭目标 Sysplorer，再更新配套客户端和插件。首次安装用 `Install-Server.ps1`；保持现有配置和凭据的 DLL 更新用 `Update-Plugin.ps1`。首次安装脚本重跑会生成新密钥，不自动保留旧密钥。

## 附录 D：常见问题

| 表现 | 检查方法 |
|---|---|
| 连接被拒绝 | B 是否启动；`Check-Server.ps1` 是否显示监听；地址和端口是否正确 |
| 连接超时 | 防火墙规则、网络配置文件、路由/VPN、B 的 IP 是否变化；A 可用 `Test-NetConnection B的IP -Port 39001` 辅助检查 |
| 建立连接后立即断开 | 访问密钥是否一致，B 最近认证错误是否为 `AUTH_FAILED`，两端是否是配套版本 |
| 缺少插件能力 / 模型不匹配 | 查看缺失字段及期望/实际哈希；退出目标宿主，使用“仅更新插件”同步配套 DLL，再从新版客户端显式重试 |
| 找不到本地 Sysplorer | 检查 `sysplorer.ini` 中 `[Host] Home` 指向的 `Bin64\mworks.exe` 是否存在 |
| 未安装配套插件 | 更新目标安装目录中的 `Bin64\addins\BatteryUdpControl\battery_udp_control.dll`，再重试 |
| Sysplorer 被占用 | 另一任务或用户操作占用了当前实例；客户端不会接管其他任务 |
| 端口占用 | 检查是否启动了多个相同端口的实例，或其他程序使用了该端口 |
| 目录/编译失败 | B 的安装与任务路径必须为英文，ServerUser 对任务目录有修改权限，编译器和许可正常 |
| 结果下载失败 | 检查 A 的目录权限、空间和网络，重试下载，不必重新求解 |
| B 状态文件显示监听，但已不能连接 | 状态记录可能来自已退出进程；检查脚本会同时核对当前 PID，确认选中了正确实例 |

## 附录 E：协议与安全边界

采用 4 字节大端长度前缀的 JSON 帧，单帧上限 1 MiB。握手通过随机挑战和 HMAC-SHA256 双向证明共享密钥；认证后每帧带方向、递增序号及 HMAC，拒绝篡改和重放。访问密钥不直接通过网络传输。请求层继续匹配会话、请求、客户端与任务标识。

**报文内容没有加密。** 参数、样本、结果及任务标识可能被同网络观察者读取，因此部署在受信任局域网或 VPN；这不是公网 TLS 服务，也不提供每个用户独立账号体系。

结果接口只允许所属任务的 `result.csv` 和 `result.json`，每块最多 48 KiB、单文件最多 128 MiB，不提供任意路径读取或代码执行接口。最多同时接入 8 个 TCP 连接，未完成认证的连接约 10 秒超时。单个宿主仍只处理一个活动仿真任务。

构建使用 Qt 5.14.2 MSVC2017 x64、VS2017 x64 工具链和配套 Sysplorer SDK。构建脚本中的路径需要与开发机一致。打包脚本支持 `-QtHome` 和 `-VcRedist`；输出目录已存在时拒绝覆盖，可传入一个新的工作树内 `-OutputDirectory`。
