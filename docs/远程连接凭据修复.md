## 当前窗口的恢复步骤

1. 在 Qt 点“连接设置”，选择远程模式。
2. 地址填 `172.19.15.159`，端口填 `39001`。
3. 完整填写该服务器原 `access-key.txt` 的内容。**认证失败时不要留空**：留空会继续复用已保存的旧凭据。本次经用户提供的正确文件在宿主机当前工作树 `logs/remote-vm/access-key.txt`，不包含在发布包中。
4. 点“保存并连接”，确认连接成功。当前用户已完成，不需要再重做。

不要运行 Install-Server.ps1、生成新密钥或降低模型检查。服务器继续使用此前已修复的启动器。

## 远程专用入口

当前工作树可双击 `app/ui/run_remote.bat`。它使用当前虚拟机地址、端口和工作树已有凭据文件，先预检，再打开本轮客户端，显式参数覆盖旧连接配置，不写用户全局设置。新界面打开后仍需在连接设置点“保存并连接”。如果预检失败则终止，不切回本机。虚拟机换 IP 时可通过批处理的第一个参数指定目标，第二个参数指定端口。

部署到其他目录/电脑时，用新客户端包内的 `Start-Remote.ps1`，显式提供实际地址、端口和原凭据文件路径。例如在客户端解压目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Remote.ps1 -Address '172.19.15.159' -Port 39001 -KeyFile 'C:\BatteryCredentials\access-key.txt'
```

`C:\BatteryCredentials\access-key.txt` 为示例，替换为该电脑实际保存的原服务器凭据文件。入口将参数传给客户端进程，随后恢复调用终端环境，不修改系统 PATH 或全局配置，不保存明文密钥。不提供任何自动发现网关、猜测凭据或降级本机行为。

原 `Start-Client.ps1`、本机入口保持原功能。已在原窗口保存正确地址和凭据的用户，可继续使用原入口。
