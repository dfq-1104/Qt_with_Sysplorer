# Qt 客户端与 Sysplorer 服务器部署操作手册

**当前启动入口和修正包以《启动与连接纠错说明_20261108》为准。** 本次工作树版 ZIP 绑定 be10；以下独立客户端部署步骤适用于未绑定的独立远程包，不能将工作树绑定文件照搬到另一台电脑。

日期：2026-11-08。源码基线为 0aab637；本轮启动脚本修正和实测结论见《双模式测试报告_20261108_be10》。

当前工作树为 C:\Users\TR\.codex\worktrees\be10\qt界面开发。按“服务器安装插件、配置端口和凭据、启动服务，客户端再连接”的顺序操作。已有部署不要重新执行首次安装。

## 一、服务器电脑

### 第 1 步：区分已有部署与首次安装

当前虚拟机地址为 **172.19.15.159:39001**。服务器自身 IPv4 地址是 172.19.15.159；默认网关 172.19.0.1 是网络出口，不是 Sysplorer 服务地址。只有另行配置端口转发时才连接转发地址。

当前服务器的认证、两项生命周期能力和模型核验均已通过。已有部署跳过第 2 步，不更换密钥，不重装插件；先检查服务，再确认使用配套启动脚本。服务器监听地址 0.0.0.0 表示监听所有网卡，不填到客户端地址栏。

### 第 2 步：新服务器首次安装插件

已有部署跳过本步。首次安装会生成新访问凭据，不能用来代替“仅更新插件”。

1. 安装 Sysplorer 并确认许可有效。当前远端配套为 Sysplorer 2026b，之前核验的宿主版本是 26.8.0.2280。本机隔离环境使用 2026a，插件分别管理。
2. 将 BatteryConsole-Server-win64.zip 解压到 C:\BatteryConsole-Server-win64，确认 DLL 与脚本直接位于该目录。使用英文目录。
3. 保存工作，手动关闭目标安装目录下全部 Sysplorer 实例。脚本不会自动结束进程。
4. 以管理员身份打开 Windows PowerShell，执行：

~~~powershell
Set-Location 'C:\BatteryConsole-Server-win64'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Server.ps1 -SysplorerHome 'C:\Program Files\MWORKS\Sysplorer 2026b' -ListenAddress '0.0.0.0' -Port 39001 -Workspace 'C:\BatteryJobs' -OpenFirewall
~~~

安装脚本默认目标是 2026a，使用 2026b 必须显式指定安装路径。若使用另一个管理员账号提权，还需传入 -ServerUser '电脑名\实际运行Sysplorer的用户名'，使凭据权限和任务目录授权正确。

| 项目 | 安装结果 |
|---|---|
| 插件 | 安装目录\Bin64\addins\BatteryUdpControl\battery_udp_control.dll |
| 远程配置 | 同目录 remote.ini，含 Enabled、ListenAddress、Port、Workspace、AccessKey |
| 客户端访问凭据 | 服务器包目录 access-key.txt |
| 部署记录 | 服务器包目录 deployment.json，不含密钥 |
| 任务与求解文件 | C:\BatteryJobs |

默认防火墙规则适用于域/专用网络中的本地子网。跨子网时按实际客户端来源配置 -AllowedClientAddress 或调整现有规则；客户端端口须与服务器监听端口一致。本轮没有重新执行真实远端首次安装或修改防火墙，插件更新保护在工作树模拟目录测试。

### 第 3 步：配置端口和访问凭据

默认使用 **TCP 39001**。服务器 remote.ini、监听端口、防火墙和客户端端口应一致。更改服务器配置后，保存工作并手动重启目标 Sysplorer。

访问凭据用于授权客户端加载模型、翻译、求解、暂停/停止、调参和下载结果。它不是 Sysplorer 许可，也不随每次仿真任务重新生成。

将服务器现有 access-key.txt 通过可信方式传给客户端用户。完整复制同一服务器的密钥，不要使用另一个包的旧值。不得把真实密钥放进代码、公开说明、截图或分发压缩包。

### 第 4 步：通过配套脚本启动 Sysplorer

服务器尚未运行时，在实际运行 Sysplorer 的账号下执行：

~~~powershell
Set-Location 'C:\BatteryConsole-Server-win64'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Sysplorer.ps1 -SysplorerHome 'C:\Program Files\MWORKS\Sysplorer 2026b' -Workspace 'C:\BatteryJobs'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Check-Server.ps1 -Port 39001
~~~

如果包仍在 C:\Users\dfq\Desktop\BatteryConsole-Server-win64，第一条命令改为实际目录。不要为了每次客户端连接再启动新实例。

等待主窗口初始化完毕。检查 Enabled=True、Listening=True、Port=39001、LastError 为空。配套启动脚本给宿主及求解器子进程提供 Bin64、Simulator\Bin64 路径，执行后恢复调用终端环境。曾出现“翻译成功，但求解器 0xC0000135 退出”的情况，加入 Bin64 后同一模型可运行；仅双击 Sysplorer 图标可能没有该启动环境。遇到 START_FAILED 仍需核对本次日志，不能仅凭现象认定根因。

服务器不需要 Qt 客户端，也不需要先手工打开模型。当前插件和 Qt 分别内置配套模型，Qt 发送哈希、控制指令与参数；插件在服务器准备模型并求解，协议不是每次把 Qt 模型全文上传到远端。

## 二、Qt 客户端电脑

### 第 5 步：解压客户端

将 BatteryConsole-Client-win64.zip 解压到固定目录，例如 C:\BatteryConsole-Client-win64，完整保留 DLL、插件子目录和脚本。不要只复制 EXE。仅远程使用时，客户端电脑不需要安装 Sysplorer。

客户端包不含 access-key.txt、服务器 remote.ini、已保存用户凭据和任务结果。服务器包也不包含合法 Sysplorer 安装和许可。

### 第 6 步：启动、填写设置并连接

~~~powershell
Set-Location 'C:\BatteryConsole-Client-win64'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Client.ps1
~~~

Qt 启动保持空闲，不自动连接或启动本机 Sysplorer。打开“连接设置”，填写：

| 字段 | 当前服务器 |
|---|---|
| 模式 | 远程 |
| 地址 | 172.19.15.159 |
| 端口 | 39001 |
| 访问凭据 | 服务器当前 access-key.txt 的完整内容 |

点击“保存并连接”。远程失败不会切成本机，也不会启动本机 Sysplorer。

**通常只需首次保存一次凭据。** 凭据按当前 Windows 用户加密保存。以后启动仍需显式连接，但无需每次重填。更换 Windows 用户、目标服务器或服务器密钥，或保存的旧值失效时，需要重新填写。输入框留空会复用保存值；认证失败时完整重填现有密钥，不要反复留空复用旧值，也不要先重装服务器。

也可以安全保存服务器现有密钥文件后显式启动：

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Remote.ps1 -Address '172.19.15.159' -Port 39001 -KeyFile 'C:\BatteryConsole-Private\access-key.txt'
~~~

该密钥路径由客户端用户自行准备，不是包内默认文件。此入口不改写全局保存值；正常启动后仍在界面显式连接。部署脚本可用 Windows PowerShell 5.1；本轮同时回归 PowerShell 7 的环境恢复。

### 第 7 步：按顺序运行一次任务

1. 连接成功后点击“加载模型”，等待加载完成。
2. 设置电压、电流、方向和起始电量，点击“保存参数”。
3. 点击“翻译模型”，等待翻译完成。
4. 点击“开始仿真”，检查仿真时间、SOC、电压、电流及曲线。
5. 按需验证暂停、继续、运行中调参和停止。停止后只有实际完成范围内的结果。
6. 等待结果下载，检查曲线和回放。结果通过网络下载，不需要共享服务器目录。

虚拟机地址可能变化。连接失败时重新查看虚拟机 ipconfig 的 IPv4 地址，不要把网关地址填成服务器地址。

~~~

远程入口使用同一客户端：

~~~powershell

~~~

仓库远程入口读取当前树 logs\remote-vm\access-key.txt 的现有凭据并预检。它属于忽略目录，不纳入 Git 或运行包。通用入口 app\ui\run_ui.bat 保留用户保存模式。

两个模式保留现有布局；在“连接设置”切换，任务空闲时操作。本机 Qt 启动不自动启动宿主，点击连接、加载、翻译或开始时才按需启动。

## 四、仅更新插件与故障处理

已有部署只更新 DLL 时，保存工作、手动关闭目标 Sysplorer，在服务器包目录的管理员 PowerShell 执行：

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Update-Plugin.ps1 -SysplorerHome 'C:\Program Files\MWORKS\Sysplorer 2026b'
~~~

脚本备份旧 DLL、校验清单及复制后的哈希，不改 remote.ini、端口、密钥或防火墙，不自动结束进程。当前已经兼容的远端无需为了本轮测试再更新。

| 现象 | 检查顺序 |
|---|---|
| TCP 超时/不通 | 虚拟机 IPv4 → Sysplorer 初始化 → Check-Server → 监听端口 → 防火墙与虚拟机网络 |
| 认证失败或认证阶段关闭 | 完整重填同一服务器现有密钥，核对旧保存值；不要先重装 |
| 能力缺失或模型哈希不匹配 | 关闭目标宿主后更新配套插件；不降低校验；显式重试 |
| 宿主繁忙 | 等待原任务结束，不抢占其他用户任务 |
| 翻译成功、开始失败 | 保留任务号、输出窗口、生成目录日志；确认启动脚本及 DLL 路径，不反复提交开始 |
| 本机连到旧插件 | 使用当前树 run_local.bat，核对 state.json、Check-Local 的实际宿主及插件路径 |
| 下载中断 | 保留任务号和已有结果，通过原连接重试下载，不重新开始任务替代下载 |

本轮安装和重启命令是部署说明，未自动在真实远端执行。真实测试结论以测试报告为准；“已连接”不等于“求解、下载和回放均已通过”。
