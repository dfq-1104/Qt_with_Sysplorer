## 1. 远端电脑：已有部署如何启动

当前虚拟机已经完成插件更新、端口与凭据配置，不再执行首次安装。

1. 保留原 `remote.ini`、`access-key.txt` 和防火墙设置。当前配套插件 SHA-256 为 `C7BEBE4A7AB85F1FEB4D9442DCA3050A8D32430F423ED1843EE770D7C64BE6EE`，模型哈希见第 5 节。
2. 解压 `BatteryConsole-Server-LaunchFix.zip`。本次位置为 `C:\Users\dfq\Downloads\BatteryConsole-Server-LaunchFix`。
3. 保存工作，手动关闭目标安装目录下的旧 Sysplorer。只有新启动的进程才能继承修正后的 DLL 搜索路径；脚本不会自动结束实例。
4. 使用日常运行 Sysplorer 的账号，在普通 PowerShell 中执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\Users\dfq\Downloads\BatteryConsole-Server-LaunchFix\Start-Sysplorer.ps1' -SysplorerHome 'C:\Program Files\MWORKS\Sysplorer 2026b' -Workspace 'C:\BatteryJobs'
```

```powershell

```

应显示 `Enabled=True`、`Listening=True`、`LastError` 为空。监听地址 `0.0.0.0` 表示服务器绑定全部 IPv4 网卡；客户端填写实际虚拟机 IP。

新版启动脚本为 Sysplorer 和求解器子进程加入**同一安装目录**的 `Bin64`、`Simulator\Bin64`，启动后恢复调用终端环境，不改变永久 PATH。原桌面服务器包的旧启动脚本没有自动替换，后续继续用上面的新入口；如需保留桌面原入口，由用户备份后仅替换 `Start-Sysplorer.ps1`，新版仍会读取原 `deployment.json`。

**远端日常只需用正确启动器启动 Sysplorer，并保持其运行。** 不需要 Qt，不需要额外常驻服务，不需要每次重新安装插件或生成凭据。

## 2. 远端电脑：新电脑首次部署

本节只供全新电脑使用，已有部署跳过，以免首次安装重新生成访问密钥。

1. 安装本次已验证的 Sysplorer 2026b x64，确认主程序能正常打开，许可与编译环境可用。
2. 将最终服务器包 `BatteryConsole-Server-win64.zip` 完整解压。示例为 `C:\BatteryDeploy\BatteryConsole-Server-win64`。
3. 关闭目标 Sysplorer，在管理员 PowerShell 中安装插件并配置端口。`-ServerUser` 使用日常运行 Sysplorer 的账号，可先在该账号终端运行 `whoami` 确认，然后替换下面示例：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\BatteryDeploy\BatteryConsole-Server-win64\Install-Server.ps1' -SysplorerHome 'C:\Program Files\MWORKS\Sysplorer 2026b' -ListenAddress '0.0.0.0' -Port 39001 -Workspace 'C:\BatteryJobs' -ServerUser '计算机名\用户名' -OpenFirewall
```

4. 安装脚本生成配套 `remote.ini`、原服务器包中的 `access-key.txt` 和 `deployment.json`，并创建指定端口规则。保存这些文件；任务目录与安装目录使用可写/可访问的英文路径。
5. 回到日常账号，用**同一最终包**内新版启动器启动，无需每次安装：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\BatteryDeploy\BatteryConsole-Server-win64\Start-Sysplorer.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\BatteryDeploy\BatteryConsole-Server-win64\Check-Server.ps1' -Port 39001
```

6. 将服务器实际 IP、端口和既有访问凭据交给客户端操作人。密钥来自该服务器包的 `access-key.txt`，不是 Windows 密码，也不是 Sysplorer 许可证。不在日志或说明中记录密钥内容。

## 3. Qt 客户端电脑：连接与操作

1. 解压客户端包，运行其中的 `Start-Client.ps1` 或 `battery_console_ui.exe`。界面启动不自动连接，也不自动启动本机 Sysplorer。
2. 点击右侧“连接设置”，选择“远程 · IP 与端口”。
3. 本次服务器地址填写 `172.19.15.159`，TCP 端口 `39001`，访问凭据填写远端原 `access-key.txt` 中的值；已保存正确凭据时可留空复用。
4. 点击“保存并连接”，等待已认证、已连接状态。若失败保持远程模式，查看具体错误后显式重试，不会切回本机。
5. 点击“加载模型”确认加载，再点击“翻译模型”，成功后点击“开始仿真”。若模型已在同一宿主加载，“加载模型”禁用属于正常复用状态，可直接翻译。开始入口也可按原逻辑自动完成必要准备。
6. 运行时可暂停/继续、调参或停止；正常完成后下载完整结果，主动停止后下载部分结果。Qt 本地校验并显示曲线，允许回放；不直接打开远端的文件路径作为本地路径。

Hyper-V Default Switch 的 IP 可能变化，以虚拟机实际网卡地址为准。本次 `172.19.0.1` 是宿主机网卡，不作为客户端目标；`0.0.0.0` 也不是客户端连接地址。
